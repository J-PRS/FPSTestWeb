# Client perf plan — friend at 0.25res on a beefy GPU

## Measured (this box, `E2E_GPU=1 bun _tools/e2e/perf.ts`)

`fps=59.6 median=16.67ms p99=16.79ms` — vsync-locked, not slow.
Phases: `player=2.1 fx=1.2 render=2.3` — hot spots:
- **`w:player=19.2ms` worst** — the per-frame remote-player pass spikes hard
- `jsBusy=34%` — third of CPU idle in GC/sched, not logic
- `heap=83MB` — small; leak classes live elsewhere
- `draws=308 tris=169k` — draw call count is the GPU budget, not tris

## The friend's actual problem

0.25 res fixing it = **fill-rate bound**. The composer chain
(`scene sanitize bloom sanitize2 dirt aces contrast fxaa>SCR`) runs
per-pixel at full resolution. At 4K/1440p on a mid GPU that's
the entire frame budget. Options:

1. **Resolution-scale the post chain, not the scene** — render scene
   at full res, run bloom/dirt/contrast at 0.5×, composite upscale.
   Free resolution for the pass that needs it (edges, HUD, scene);
   the blur passes are blur anyway.
2. **Cheap-AA path: FXAA-only, skip composer** — `pmode=RAW` + FXAA on
   the raw buffer skips the whole composer chain (one pass total).
   Already supported (`fxaa>SCR` vs the full composer) — make it a
   first-class "low GPU" preset, not a debug.
3. **Bloom on its own target** — bloom at quarter-res ping-pong is
   standard; ours runs the full chain at scene res.
4. **Draw call budget** — 308 draws; instancing audit on debris/
   healthbars/pickups (they're likely individual meshes).

## w:player=19.2ms spike — the remote-player pass

Per-frame work that spikes on player joins/remotes — candidates:
`remotePlayers` material/prop updates, health-bar creation on first
sight, name-plate canvas textures. Worth instrumenting which sub-step
spikes (updatePlayerBars? markPos? indicator textures?).

## Research (2026-10-25): the standard fix is pass MERGING, not downscale

- pmndrs/postprocessing EffectPass merges per-pixel effects into one
  compound shader — dirt/aces/contrast are the same op shape (read,
  transform, write). 5 framebuffer roundtrips → 1. Unity abandoned its
  multi-pass stack for exactly this.
- three.js UnrealBloomPass = fixed 5-mip separable Gaussian, ~270
  taps / 10 passes regardless of radius. Jimenez dual-filter bloom
  (SIGGRAPH 2014) = downsample pyramid + tent upsample, ~9× faster
  and it IS the half-res chain by construction.
- Bart Wronski (console guidelines): fullscreen passes cost read+write
  bandwidth — fix is fewer passes and smaller targets, i.e. merge.

## Recommendations (pick what to approve)

**Ship first (researched, replaces the raw downscale idea):**
- R1': merge dirt+aces+contrast+sanitize into ONE composite pass;
  FXAA runs at full res (in the pass or after it)
- R2': replace UnrealBloomPass with the dual-filter down/up pyramid —
  cheaper per frame AND the radius becomes a real dial
- R3': "Low GPU" preset = RAW pmode + FXAA + postpro off — bundle
  the existing flags into one labeled setting

**Investigate then fix:**
- R4: Instrument the remote-player pass (which sub-call spikes
  w:player to 19ms)
- R5: Draw call census (Alt+Q instPools shows instanced groups —
  find what's still per-mesh: debris? pickups? bars?)
- R6: Species/balls OFF by default on production (user already
  asked for no-balls-no-creatures; confirm the public build ships it)

**Bigger, deferred:**
- R7: Worker-side sim (netSim in a worker — frees main-thread CPU,
  big change)
- R8: Batched player health bars (one instanced mesh, not per-player canvas)
