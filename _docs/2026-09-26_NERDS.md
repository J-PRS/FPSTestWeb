## The interesting stuff from the nerds

**Hermite/Catmull-Rom spline interpolation** — HoloScript, Veloren (`ENABLE_POSITION_HERMITE`), and coherence all interpolate position on a *cubic* curve using reported velocity as tangents instead of straight-line lerping between snapshots. Segments join C¹-continuously, so strafes and direction changes trace smooth arcs instead of zig-zags.

**Adaptive jitter-scaled render delay** — Mirror (`DynamicAdjustment`), Unity Netcode (`InterpolationDelayJitterScale`), and elura-netcode all compute buffer delay from *measured* arrival jitter (`sendInterval + jitter×k`, clamped) instead of a fixed constant. Clean connections get minimum delay; jittery ones auto-cushion.

**Playback timescale catch-up/slowdown** — Mirror's `Timescale()`: when the buffer underruns/overruns, instead of snapping you speed playback ±10-20% for a few frames. Invisible drift correction. (Our extrapolation+blend already covers this — noted below.)

**CS2 sub-tick** — not interpolation at all: events carry *exact* timestamps inside ticks so ordering isn't quantized to tick boundaries. Relevant only for hit-reg precision, needs server timestamps on shots.

**Interpolation-vs-prediction per-entity** (SnapNet/Unity ghosts) — we've effectively done this: remotes are pure-interpolated now, local player is predicted. Confirms the knockback removal was the right call.

## Implemented just now

- **Cubic Hermite between snapshots** — uses the `vx,vy,vz` already in each snapshot as tangents. With an **overshoot guard**: if the curve deviates from the linear result by more than half the segment length + 0.5m (stale velocity data), it falls back to lerp — the classic failure mode of Hermite with noisy tangents.
- **Adaptive render delay** — each update measures the arrival gap vs the 50ms send interval; an EMA jitter estimate drives `interpDelay = 100 + jitter×2`, clamped [80, 300]ms. Wired connexion → ~100ms latency floor; jittery Wi-Fi → auto-grows toward 300ms instead of dropping to dead reckoning.

## Deliberately skipped (for now)

- **Kalman-filter prediction** — theoretically optimal state estimation, but it's a physics-doubling exercise (same trap as predicted knockback) and the gains over Hermite+adaptive delay are marginal for player-controlled motion, which is inherently unpredictable (Gambetta's point: dead reckoning is useless on entities that can change direction instantly).
- **Catmull-Rom** — needs 4 samples (adds ~50ms latency) and can overshoot through walls on sharp turns; Hermite with known velocities is strictly better for us.
- **Timescale drift** — our 250ms extrapolation cap + reconcile blend already handles underruns gracefully; the timescale trick adds a subtle speed wobble for marginal benefit.
- **Sub-tick shot timestamps** — real hit-reg improvement but a server protocol change; if hit-registration feels off at high ping, that's the next layer to attack (attach ms-precision client timestamps to shot events).
