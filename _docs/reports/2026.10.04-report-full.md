# FPSWebTest — State of the Project (2026.10.04)

Full audit of the codebase as it stands. Read-only pass — no commands run;
all findings verified by reading the source.

---

## Verdict

The codebase is in **good shape**, and the weakest layer two weeks ago
(networking/session lifecycle) is now the strongest. The remaining debt is
*weight*, not *correctness*: god objects that are pinned but not shrinking,
dead files still in the tree, and a breadth of systems that outruns the
integration budget.

The architecture rules are real because tests enforce them — shared purity,
authority funnels, and the 900-line size ceiling are all pinned by the suite,
not by convention.

---

## 1. What the project is

A Tribes/Quake-style browser FPS: skiing, jetpacks, authoritative combat,
projectiles, multiple weapons + belt items, teams (alpha/bravo), 6 modes
(nuggets/ctf/dm/tdm/rabbit/duel), procedural terrain + heightfield maps,
deployables, bots with brains on both ends, creatures, demos/replays,
telemetry, and custom model/animation/VFX systems.

Target deployment: static client on surge.sh, Bun authoritative server
behind a Cloudflare Quick Tunnel.

Structure:

- `shared/` — deterministic sims + protocol contract (~50 files, purity-pinned)
- `server_bun/` — Bun authority: rooms, tick loop, combat, session registry
- `client/` — Three.js render + prediction + input
- `maps/` — heightfield + structure specs
- `_tools/` — e2e harness, bake pipelines, one-off utilities

## 2. What's genuinely good

### The wire contract is a model file

`server_bun/src/wire.ts` — one table entry per client→server message:
validator + rate-limit bucket + room handler. Validation runs pre-room
(`GameServer.validate`), handlers run inside the room's command drain at
tick phase 0. A new message type is one entry, not a three-file change.
The comments document *why* limits are shaped the way they are (teleport
deliberately unlimited — a drop only desyncs; environmentDamage's 30/s
bucket sized for crawler-pounce bursts).

### The command queue landed

`GameServer` pushes validated messages to `room.commands`; `TickLoop`
drains them as phase 0 before sims/fanout. Arrival-time mutation is gone —
the ordering class of bug that produced the flaky netbot test now has a
defined boundary.

### Sessions are a real state machine

`sessionRegistry.ts`: `connecting → active|spectating → grace → reaped`,
illegal transitions logged as anomalies, generation-stamped sockets so
stale callbacks are no-ops by construction. Grace timers now live *inside*
the session (`registry.disconnect(id, reason, ms, cb)`) — the
`room.disconnected` map is fully gone; `graceInRoom` is a query, not a
store. Reclaim checks the token before the disconnected test, bypasses
join throttle, re-stamps `lastSeen`, rotates semantics safely.

The three production killers from earlier sessions (anti-cheat kick loop,
join-throttle lockout, idle-reap loop) each had the same shape — a verdict
system deciding a live player was dead with no single place to check it.
That shape no longer exists.

### Delivery guarantees are protocol-level

Reliable frames journal with a room-scoped `ev` seq; reclaim presents
`resumeSeq` and replays only missed frames, with a 3s volatile TTL on
transient events (`playerShot`/`jump`/`knockback`/`claimAck`…) so a
rejoining player doesn't get phantom cues. `claimSeq`/`claimAck` give every
claim a classified verdict — accepted / rejected(reason) / superseded /
transport-lost. Protocol v12.

### Two clocks, enforced

`wallClock.ts` is the single `Date.now()` seam, adopted across ~20 server
files (claimLedger, moveJudge, respawn, RateLimiter, combat*, SessionManager).
`simNow()` drives sims. The wall/sim distinction is structural now.

### Shared/ is actually pure

Zero `Date.now`, `performance.now`, timers, or env reads across the shared
tree. `Math.random` appears only as injectable defaults
(`rollCreatureDrop(r0, r1)`, seedable `botRand`). `sharedPurity.test.ts`
pins it.

### Testing is layered correctly

~450+ unit tests + 124 scenario files (one staged interaction each, brains
silenced so scripted shots are the only variable) + hypersoak + e2e
puppeteer harness + `sizeWatch` line-ceiling guardrails. Changelog entries
record *measured* findings. The suite is why the rules hold.

### Transport fallback preserved correctly

WS is the production default (no `?net=` → straight WS, zero probes).
`?net=auto` probes WT+RTC in parallel and falls back; `?net=wt|rtc|ws`
pins. Losing probes are muted and torn down; negative miss cache and a
flap breaker bound the retry cost. The session registry treats a transport
swap as a seat re-attachment, not a new player. RTC carries two lanes:
`game` (unordered/bounded-loss) and `ctrl` (reliable/ordered). Client
`minUptime` damper (<5s uptime → 4× backoff) plus a bounded outbound queue
flushed on reclaim.

### Feature velocity is still happening *inside* the architecture

Recent work — Concussion grenade (flag-strip payload mirrored server/
offline), CTF personal-points economy (`CTF_PTS` shared so offline pays
identically), flag dais stands as structure colliders, pending-loadout
banking per armor tier, RibbonTrail `follow` head-pinning — all went
through the shared tables and event funnels rather than around them. The
architecture is carrying new features, not fighting them.

## 3. Biggest remaining issues

### 3.1 God objects — pinned, not shrinking

| File | Size | Contents |
|---|---|---|
| `client/src/networking/NetworkManager.ts` | ~1208 lines, ~66 methods | transport + claim ledger + 4 diagnostic censuses + prediction history + presence |
| `server_bun/src/Room.ts` | ~880 lines | wiring hub — better structured (sims[] registry, drainCommands) but still the converge point |
| `server_bun/src/MessageHandler.ts` | ~640 lines | `h.moves`/`h.combat` sub-handlers keep growing |
| `client/src/entities/PlayerModel.ts` | ~985 lines | |
| `client/src/effects/vertexAO.ts` | ~900 lines | known lint debt (complexity ~48, one ~162-line function) |

`sizeWatch` pins growth — nothing reduces these. NetworkManager is the one
true god object left; the natural split is transport/session adapter,
claim ledger, replay cursor, telemetry, presence.

### 3.2 Dead files still in the tree

- `client/src/gunlab copy.ts` — 33KB duplicate, space in the filename,
  still typechecked, still hit by every grep/refactor.
- `client/gunlab copy.html` — its entry point.
- `client/src/networking/UWSAdapter.ts.deprecated`,
  `WSAdapter.ts.deprecated` — dead adapters in a live directory.
- `_zzz/`, `_DEMO/` — archive directories at repo root.
- `overview_v3.py` — stray root-level utility.

Harmless at runtime; the cost is "can't tell what's load-bearing." Cheap
win: delete or move to a `_graveyard/` outside `src/`.

### 3.3 Parallel pipelines that never collapse

- **Weapon rendering**: procedural geometry → baked GLB → `_ao.png` →
  `_edge.png` → `_grime.png` → runtime atlas fallback → CSG union preview
  in gunlab. Six fallback layers; `vmBaked.ts` is where the seams show.
  Every weapon touch reasons about all of them.
- **Demo/recording**: ~15 files (DemoManager/Recorder/Player/Serializer/
  VideoRecorder/demoWire/demoExtract/coolShots×2…) — the second-largest
  subsystem; hasn't been audited for load-bearing status.
- **Transport tiers**: dormant RTC/WT adapters (~380 lines client + two
  server adapters) — correctly preserved, but still maintenance surface
  with no telemetry justifying it yet.
- **Fire-rate enforcement has three implementations** — `fireWindows`
  cadence gate, the stampless-flood detector in `shotClaims.ts`, and
  per-type wire limits. Each catches different abuse; individually correct,
  but "can this player fire now" is answered in three places.

### 3.4 Breadth outruns depth — the systemic risk

~3 games' worth of systems (creatures, dual bot brains, deployables,
perks, classes, 6 modes, demos, P2P hosting, gunlab, bake pipelines, TTS)
on 1 game's integration budget. Every feature passes tests; every feature
also pays an integration tax across RoomInfo callbacks, offline/online
funnel parity, and HUD surfaces. The heal-grenade-for-bots-only gap was
that exact tax. `roomEvents` + the `sims[]` registry + WIRE + `worldState()`
are the right "register, don't wire" counter — RoomInfo still holds ~50
optional callback fields where features pay the old price.

### 3.5 Smaller but real

- `.git` ~338 MB — history carries large old blobs (ualgrab/zzz-era).
  Working-tree cleanup doesn't shrink clones; only filter-repo would.
- `changelog.txt` ~1900 entries + `_reports/` + AGENTS files — knowledge
  spread across three formats; the changelog is the de-facto design doc.
- `shared/` imported via `../../shared/` relative paths everywhere — a
  tsconfig path alias would kill a class of import bugs.
- All gates are manual (`tsc`, `vitest`, `bun test`, `oxlint`, e2e) — the
  650+ test suite's value depends on remembering to run it. No CI.
- `vertexAO.ts` lint debt noted above.

(server tells a drifting client it's behind — the Quake/Source pattern;
`inputMove` has `seq` but no skew-correction path) and finishing the
**RoomInfo → domain-event** migration.

## Bottom line

Architecture: sound, enforced by tests, and now cleanest exactly where it
was weakest. Risks: known, bounded, and mostly about size and duplication,
not correctness. The project is closer to "deploy and play with a friend"
than the code mass suggests — the remaining work is weight reduction, not
repair.
