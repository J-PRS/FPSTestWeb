## The SOTA pattern (every source agrees)

**"Traffic lights, not traffic rules"** — deterministic mechanisms that block, outside the model's reasoning. Lint/CI errors can't be ignored the way docs can. In descending strength:

1. **Hooks with non-zero exit** — literally can't be bypassed
2. **Verification gates per task class** — agent's self-assessment is the *least* reliable signal; test output is the most reliable. Gate on tests, not on "model thinks it's done"
3. **Lint as context injection** — error messages written as *remediation instructions* ("move to shared utils because..."), not just "invalid X". The bug→rule ratchet: every observed defect becomes a lint rule so it can never recur
4. **Staged-files-only pre-commit** (<5s, lint/format/typecheck) + **full suite in CI/heavier pass** (minutes). Hooks that take 30s get `--no-verify`'d into uselessness
5. **AGENTS.md**: six parts only — verified commands, boundaries, local context, *definition of done*, placement rules, prune date. Growing it per-mistake makes it worse; repeated corrections belong in code/lint, not prose
