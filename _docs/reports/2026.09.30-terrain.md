## The fundamental problem

Tiling = periodicity. Any field that's seamless across a boundary must repeat; the only question is *where the repetition lives* and whether players perceive it. Three families of solutions, in order of how modern practice ranks them:

## 1. Periodic lattice noise — what you already use

Take Perlin/simplex, wrap lattice coordinates mod N at the gradient lookup (`perlin-numpy`'s `tileable=(True,True)` does exactly this). Guarantees C1 continuity — heights *and* slopes match at the seam, which matters for skiing.

- **Costs**: the base octave's period must divide the tile evenly (your `_validate_tiling_constraints` already enforces `res * lacunarity^(octaves-1) | size`), and every octave must be an integer multiple of the base period or the seam returns at the detail level.
- **The honest critique**: it repeats exactly. Your 3×3 image shows it — the same basin cluster every tile. This is the *cheapest* seamless method but the most visually obvious repetition.

## 2. Toroidal/4D embedding — the modern standard trick

Map 2D UV → two circles embedded in 4D space, sample a 4D noise there:

```
nx = cos(2π·u)·r, ny = sin(2π·u)·r
nz = cos(2π·v)·r, nw = sin(2π·v)·r
```

Since `cos(0)=cos(2π)`, opposite edges are *literally the same samples* — C∞ continuous, no lattice constraint, works with **any** noise family (simplex, open-simplex2, Worley/cellular, even correlated multi-noise). Libraries exist everywhere (`tiling-noise` JS, `symbios` Rust, Godot's `Noise4DTexture2D` `seamless` flag is this internally).

- **Trade-off**: 4D noise is ~2× the cost of 2D, and the domain gets stretched along the torus circumference (`r` controls how many noise cells fit around the loop — larger r = more detail per tile but the field curves through 4D space, which slightly warps feature shapes at high r).
- **For you**: this frees you from `perlin-numpy`'s integer-lattice requirements and lets you use better noise (open-simplex2 doesn't have Perlin's axis-aligned artifacts).

## 3. Non-periodic tiling — kill the repetition entirely

The repetition problem isn't solved by better noise — it's solved by *not repeating the same field*:

- **Wang tiles** (the ACM paper result): a small set of tiles whose edges are designed to match each other in multiple ways, arranged stochastically so the plane tiles aperiodically. A handful of "seam-compatible edge variants" → arbitrarily large non-repeating terrain. The trick that works on textures works on *heightmaps*: generate N tiles whose edges are mutually compatible (constrain edge rows/cols to a shared profile), then permute them at sample time. Client samples `fract(worldXZ/scale)` → hash the integer tile index → pick which variant → seamless AND non-repeating.
- **Stochastic/jittered grids**: sparse-convolution noise (scatter features at hashed positions within each tile, wrap feature kernels mod the tile size) — Worley/cellular noise does this natively. Rivers, craters, and rock scatter live here.

## 4. Erosion — where terrain stops looking procedural

The reason generated terrain looks "samey" isn't the noise — it's that raw noise lacks the *history* real terrain carries. Modern practice layers erosion sims on top:

- **Particle ("raindrop") erosion** — Beyer/Hans-Theobald algorithm: drop N particles, each flows downhill, erodes where fast, deposits where slow. Cheap (70k particles erode 1024² in seconds), produces dendritic drainage networks — the actual tell that sells "real terrain." `erodr`, Unity compute-shader ports, `soilwebgpu` all implement it.
- **Shallow-water / virtual-pipe** — grid-based fluid sim; better for rivers/lakes, heavier.
- **Thermal/talus erosion** — your `apply_erosion` is the baby version (slope-proportional blur). Real thermal erosion moves material only above the talus angle and deposits downhill — produces proper scree slopes and cliff faces.
- **Multiscale scheduling** — the modern trick: erode a coarse field first (fast, sets the big valleys), upsample, erode again. Cheaper and more realistic than hammering the full-res field.

## 5. The "make it read as terrain" shaping toolbox

- **Domain warping** (`noise(p + k·noise(p))`) — distorts the lattice so ridges bend organically instead of reading as a grid. Usually the single highest-impact upgrade after erosion.
- **Ridged transform** (yours: `(1-|n|)²`) — correct; combine with warp for real mountain look.
- **Analytical derivatives** — modern tiling simplex implementations (the JCGT paper) compute exact gradients along with the value. Use them to drive slope-dependent erosion rates and texture splatting *without* a finite-difference pass.
- **Feature modulation** — mask octaves by a low-frequency control field (e.g., "mountain belt" mask suppresses detail in plains). This is how you get *variation across the tile* instead of uniform noise density.

## What I'd actually recommend for your pipeline

Your constraint is unique: server and client must sample **bit-identical** terrain, so the field must be baked, not procedural at runtime — which is exactly what you have (PNG→bin). So the generation side is free to be heavy:

1. **Keep the PNG pipeline.** Bake offline, ship a texture, sample deterministically. ✅ already correct.
2. **Add toroidal 4D noise** — better noise quality than periodic Perlin, same tileability guarantee, no lattice divisibility constraints.
3. **Add particle erosion** (`erodr`-style, offline in the Python gen — `numpy` version or call out to a compiled tool) — this is what will make generated terrain *read* as terrain instead of noise.
4. **Wang-tile it for the real fix** — generate ~4 edge-compatible variants per biome, hash tile index → variant on the client. Removes visible repetition at zero runtime cost. This is the single biggest visual upgrade available; everything else is detail.
5. **Keep `genfield.js`'s authored features** — flats/craters at world coords is how bases sit on generated terrain; keep that concept layered *on top* of procedural base.

The deep-end reading: the JCGT tiling-simplex paper (analytic gradients + tiling), the ACM Wang-tile noise paper, and `soilwebgpu` (Nicholas McDonald's soillib port — the best single reference for what "modern" terrain gen actually looks like end-to-end).
