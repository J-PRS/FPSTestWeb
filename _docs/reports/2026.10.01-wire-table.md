# WIRE — one table for the client→server message contract

## Before

Adding a message type touched three files:

- `validation.ts` — `VALIDATORS[type]` (wire bytes → typed message)
- `config.ts` — `rateLimits[type]` (per-type bucket, plus a dead `input` entry)
- `MessageHandler.ts` — `handlers[type]` (dispatch)

Three partial tables keyed by the same `ClientMessage['type']` — drift-
prone (a validator without a handler reads as an unexplained drop; a
rate limit without a validator is dead config, which is exactly what
`input` had become).

## After

`server_bun/src/wire.ts` — `WIRE[type] = { validate, limit?, handle }`.
One entry is the whole contract for a message type.

- `validateMessage` moved to wire.ts (reads `WIRE[type].validate`).
- `RateLimiter` reads `WIRE[type].limit` via `wireLimitKey`/`wireLimit`;
  unlisted types share the `default` bucket as before.
- `MessageHandler.handleMessage` dispatches `WIRE[type].handle(this, id, m)`.
  Its per-handler internals (`moves`, `combat`, `roomInfo`, `ballSim`,
  `creatureSim`, `claimAck`, `sendWorldState`, `handleSnapshotRequest`,
  `relayPresenceEvent`) went public — WIRE handlers take `h` as the first
  arg, so the table lives outside the class.
- `validation.ts` keeps the primitives (`validateVec3`, `validateBody`,
  `optVec`, `optClaimSeq`, `validatePlayerId`, …) — wire.ts imports them.
- `config.rateLimits` deleted (incl. dead `input` entry). `join` stays
  out of WIRE (handshake path, pre-room); `switchRoom` validates but
  carries no `handle` — GameServer intercepts room hops.

Dispatch order is unchanged: GameServer validates at the socket,
`room.commands` buffers, and the handler runs at tick phase 0 under the
rate limiter.

## Verify

- `bunx tsc --noEmit` clean (server); client tsc clean (host.ts p2p path
  re-points to `wire.js`).
- `bun test` — 737/737 including the validation coverage suite and the
  real-socket netbot tests.
