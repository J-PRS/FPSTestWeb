SOTA answer, in order of fit:

- **`xatlas`** (C++, the industry standard — same lineage as Thekla/The Witness). JS wrappers: `xatlas-three` (three.js `BufferGeometry` unwrap via WASM worker — the drop-in), `xatlas.js`/`watlas` (raw WASM APIs), `uvunwrap` (pure Rust, builds to wasm, `Density::Fixed { texels_per_unit }` = your exact "X px per Y area" requirement).
- **Your own precedent** — and the fun one: the wear-mask atlas in `vertexAO.ts` already does exactly the "every tri detached" strategy (`WEAR_CELL = 32` px per tri cell — no continuity, just rasterized cell packing). For a bake-only map, detached per-tri cells are legitimate: xatlas charting exists to avoid seams in *continuous* textures; AO/wear masks don't need continuity, they need non-overlap + density.

So the honest lazy answer: you don't even need xatlas — a per-tri cell atlas (the mechanism already written for the wear shader) IS the detached-vert unwrap. xatlas is the answer if you want nicer packing/bilinear filtering later.
