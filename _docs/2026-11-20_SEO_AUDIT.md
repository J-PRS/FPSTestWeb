# SEO audit — anabatic.gg (2026-11-20)

Full indexability audit of the live site plus browser-game SEO research.
Every finding verified against the live deploy (`d6667c38` frontend `201bcabf`).

## What a crawler sees today

`curl https://anabatic.gg/` returns the SPA shell. Verbatim inventory:

| Signal | Present? |
|---|---|
| `<title>` | `Anabatic` — only tag that exists |
| meta description | none |
| canonical | none |
| Open Graph / Twitter cards | none |
| structured data (VideoGame) | none |
| robots.txt | none — SPA fallback 200s it as text/html |
| sitemap.xml | none — same fallback |
| manifest.json | none — same fallback |
| H1 / body text | none — body is the menu skeleton: RECORDINGS, PROFILE, GAME, PERFORMANCE labels + "Click to Resume" |

Google renders JS, but the rendered DOM is a WebGL canvas — a canvas is
opaque to indexing. Effectively Google can index a page whose entire
relevance signal is the word "Anabatic". It will rank for the literal
name and nothing else.

Social side is worse for a game whose growth channel is shared links:
every URL — `/` and `/s/<clip>` alike — unfurls as a bare link in
Discord/X/WhatsApp/iMessage. The cool-shot share links are already
built for virality; they currently post as naked URLs.

Already good: HTTPS + 1y HSTS, `www→apex` 301, `nosniff`, Cloudflare
edge caching, fast TTFB, viewport meta, fast first paint.

Soft-404 risk: the SPA fallback 200s *every* path (`/robots.txt`,
`/sitemap.xml`, `/anything`). That is correct for `/s/` links, but
Google interprets infinite 200s as a soft-404 farm over time. Mitigation
is cheap (robots.txt + sitemap exist as real files; arbitrary junk URLs
stay 200 but at least are no longer the only signals).

## Research takeaways (browser-game SEO)

- Canvas games rank on the text *around* the game, not the game.
  Standard page: `Play <Name> — <genre> browser game` title, ~150-char
  meta description with a call to play, one H1, a few H2 sections
  (how to play / controls / features). Written for players, not stuffed.
- `VideoGame` schema.org markup gives Google the genre/platform/free
  facts in machine form (rich-result eligible for SoftwareApplication
  family).
- Link previews run on raw HTML only — Discord/crawlers never execute
  JS. OG tags must ship in `index.html` itself; a runtime-injected tag
  is invisible. Card image: absolute URL, 1200×630.
- For games, portal listings matter more than classic SEO: itch.io
  (free, non-exclusive), Newgrounds Portal (community vote),
  CrazyGames (requires their SDK), Poki (web-exclusive deals).
- Shared links get opened on phones — the game needs a keyboard/mouse,
  so a first-screen "best on desktop" note prevents rage-quit bounce
  (bounce rate is a ranking-adjacent signal).

## Competitor playbook — how the browser-FPS niche actually grows

Narrow look at the games Anabatic sits next to. Sources linked in each
bullet.

**Krunker.io (Yendis)** — the genre's flagship and the closest model.
- Rode the 2018 `.io` wave from an existing funnel (vertix.io already
  had 5M plays) — cross-game traffic, not cold SEO.
- Retention mechanics, in order: account system (stats persist →
  players come back), map editor (players rebuild CS/CoD maps →
  UGC they share themselves), a competitive scene that makes montages
  on its own. The updates cadence never stopped.
- Creator economy was mostly organic; paid influencer pushes exist but
  are bolt-ons (RU campaign: ~90k stream views, ~700k YouTube views).
- 2024+: FRVR ported it to Discord Activities — playing inside the
  social platform is the current evolution of distribution.
  (ioground history, RMAA case study, Discord build case study)

**Venge.io (ONRUSH)** — 50M+ plays, the honest answer to "who markets
it": Poki does. Poki reached out on Twitter; the studio ignores
marketing entirely — "the only platform on web that properly advertises
your game". Streamer/TikTok spikes happen but are random and
unactionable. (Poki blog interview)

**Shell Shockers (Blue Wizard)** — the demographic data nobody else
publishes: the real market is schoolkids, 39% on *Chromebooks*, mostly
US+BR+EU. Revenue ~80-90% ads + cosmetics/VIP, low seven figures/yr.
Its traffic leans hard on the "unblocked games" mirror ecosystem.
(gamediscover.co deep dive)

**The unblocked-mirror channel** — schools filter by domain
reputation, not content; games spread via mirrors on whitelisted hosts
(github.io, Google Sites, iframe embeds). Being iframe-able is the
entry ticket — and `X-Frame-Options: DENY` on anabatic.gg currently
closes that door entirely.

**What this means for SEO specifically**: in this niche, search volume
is *navigational* — "krunker", "venge.io unblocked", "shell shockers".
Nobody ranks for "best browser FPS"; the winner owns their brand SERP
and gets found via portals, creators, and mirrors. So the P0/P1 work
isn't about ranking for keywords — it's about converting every future
mention (a clip shared in Discord, a stream, a portal listing, a mirror)
into a working funnel: preview card → page loads → play button.

## Plan — ordered by impact per effort

### P0 — indexability floor (one commit, all static files)

Status 2026-11-20: **zero-copy items DONE (staged, undeployed)** —
`robots.txt` (+ `Disallow: /wtmin.html`), `sitemap.xml` (`/` +
`/servers.html` + lastmod), `<link rel="canonical">`, `theme-color` +
`color-scheme` metas, `preconnect`/`dns-prefetch` to play.jprice.app,
`apple-touch-icon`, and `X-Robots-Tag: noindex` on `/wtmin.html` in
`_headers`. **Copy items staged for JP approval** — every string lives
in `2026-11-20_SEO_COPY_DRAFT.md`; nothing user-facing ships unsigned.

1. `client/index.html` head: meta description, canonical, full
   `og:` + `twitter:` card set (title/description/image/url),
   `VideoGame` JSON-LD block. All static — no JS needed since crawlers
   and unfurlers read raw HTML.
2. `client/public/robots.txt`: `Allow: /` + `Sitemap:` line.
3. `client/public/sitemap.xml`: the indexable URLs (`/` + the
   `/servers.html` browser page; everything else SPA-falls back).
4. `client/public/og.png`: 1200×630 share card — a real gameplay
   screenshot with the wordmark, not the icon. Absolute URL
   `https://anabatic.gg/og.png` in the tags.
5. `client/public/site.webmanifest` + `<link rel="manifest">`: name,
   icons, `display: fullscreen` — also fixes mobile "add to home".

All five are static files — the worker's `not_found_handling:
single-page-application` only kicks in after a real-asset miss, so
files in `client/public` ship straight through `vite build` → `dist`
→ deployed on the next `_deploy_cf.bat` run. No worker code changes.

### P1 — crawler-visible copy (the actual ranking signal)

The SPA shell is the right shape for players but wrong for crawlers.
Fix without disturbing the game: a static, crawl-friendly block inside
`index.html` — visually hidden or rendered as the loading screen's
underlay — containing the H1 (`Anabatic`), a 2-3 sentence description
(browser FPS, Tribes-style skiing, free, no download), and a compact
"how to play/controls" section. It is real content the page serves;
the game paints over it once boot completes. This is the single
change that gives Google something to rank.

### P2 — share-link previews that sell the clip (structural, later)

`/s/<clip>` unfurls the same generic card as `/`. The viral upgrade is
per-link OG: the worker would need a `main` that emits HTML with a
clip-specific `og:title`/image (e.g. `og:image` = a JPEG frame or the
clip's thumbnail). Static-assets config today has no `main`; adding one
turns asset hits into (still cheap) worker invocations for HTML only.
Defer until clips are a proven traffic source — measure share-link
opens first (Discord posts + CF analytics) before building it.

### P3 — distribution (non-code, highest ceiling)

The niche evidence says this is where the players actually come from:

- **Poki/CrazyGames partnership** — the single highest-leverage move.
  Venge's 50M plays came almost entirely through Poki's promotion;
  their deal is a revenue-share where *they* do the marketing.
  Gatekeeping detail: portals iframe games — `X-Frame-Options: DENY`
  currently blocks that; swap to CSP `frame-ancestors` naming the
  portal domains when a deal is real.
- itch.io + Newgrounds listings: free/non-exclusive, the arena-shooter
  audience lives there, and each listing is a quality backlink.
- **Discord server + clip-share loop**: the `/s/` links with real
  preview cards are the cheap version of Krunker's montage economy.
  Longer-term, Discord Activities is where Krunker itself migrated.
- **Retention stack from the Krunker playbook**, when growth work
  starts: persistent accounts/stats first, community maps second
  (the map spec format already exists — a community-map pipeline is
  cheaper here than in most games), regular update cadence always.
- **Chromebook reality check**: this audience plays on school laptops —
  the game's keyboard/mouse requirement is fine (Chromebooks have
  both), but first-load weight and tick latency decide whether the
  mirror crowd stays. Worth one profiling pass before pushing portals.

### Explicitly skipped

- Prerendering/SSR the whole app: heavyweight for zero gain over the
  P1 static block — the game content itself can't be indexed anyway.
- HSTS preload: already decided against (2026-11-16 eval doc).
- Keyword/blog content: no surface for it; the game is the product.
- `X-Robots-Tag` on `/`: nothing to exclude — applied only to the
  `wtmin.html` test page.
