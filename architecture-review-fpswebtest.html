The headline: C5 landed — one world model

  • shared/worldModel.ts (633 lines) is now the single declaration point — all seven entity kinds (ball, creature, deploy, flag, pickup, projectile, player) declare {verbs, fields, spawnFields, updateFields, goneFields, rosterFields, events, simFields} once.
  • Every server→client payload generates from the table — verbPayload/spawnPayload/rosterRow/eventPayload; six roster feeds incl. gameState; all lifecycle + FX notifies (playerHit, playerKill, knockback, playerRespawn, teleport, turretShot, mineBoom…).
  • Both wire directions are inbound-checked — checkPacket on the client dispatch, checkIntent over a new CLIENT_INTENTS table on the server dispatch. A missing declared field warns at dispatch, not three frames later.
  • Five hand-written hash bodies collapsed into one replicaHash(kind, roster) (−122 lines) — hashed fields now change by declaration only.
  • Conformance test pins the table to reality — 40 checks: declaration ↔ protocol-union members, binary ballSegment + v3 tick-record round-trips, simFields subset, every ClientMessage member declared both ways.
  • Combat is claimless — SERVER_SIMMED_WEAPONS covers all ballistic weapons; clients send shotFired intent, the server sims and echoes projectileCreated(shotId). The old claim-adjudication warn classes are structurally impossible for those weapons.
  • Membership is single-owner — roster/snapshot feeds create; edges patch-or-drop (patchRemotePlayer); audit heals symmetric. The §2.156–2.169 same-class desync tail is closed by construction.

1 · Client entity classes vs shared sims — the last duplicated world

Files: client/src/entities/* (Ball, PlayerModel-driven remotes), client/src/game/net/*, shared/*Sim.ts

Problem: C5 closed the wire surface — declaration → emit → check → hash is one pipeline now. But the client still maintains parallel entity implementations: a client Ball class with its own step + presentation, client remote-player records with their own field semantics, demo/playbackReconstruction as a third truth. The world model declares what fields exist, not which code owns them. Every remaining desync class is now "client kept its own copy of state X" — the same bug family, one level up.

Solution: extend the declarations to entity construction: kind.make(id, spawnMsg) produces the client replica (a record + the shared sim step + a presentation adapter), so client classes become thin renderers over the same records the hash diffs. The demo subsystem then replays the same records instead of reconstructing a parallel entity truth. This is the "client runs a mirror of Room" half of C5 that isn't done yet — the wire is declared; the objects are not.

Benefits: kills the last copy — hash input = render input = sim record, one object. The replica-entity split (state vs presentation) mirrors what the server already does. Big honest caveat: this is a multi-session refactor touching every render site; land it per-kind, balls first (they're already shared-simmed).

2 · Split the anim state machine out of PlayerModel

Files: client/src/entities/PlayerModel.ts (1456, ~112 private members)

Problem: carried from last review, still top file — five jobs in one class: animation state machine (clip cache, fade ledger, transitions, stall guard), far-LOD variants, gibs, collider gizmo, gun attach. §2.145's T-pose bug was a seam bug between two internal rules — exactly the class this split exists to make testable.

Solution: same as before: extract PlayerAnim (mixer, fades, transitions, stall guard) behind play(name)/update(dt); PlayerModel keeps mesh/gibs/gizmo/gun. The transition table becomes headless-testable.

Benefits: locality + leverage — anim invariants in one ~600-line module that a fake mixer can drive in a test.

3 · The room audience seam (Room residual plumbing)

Files: server_bun/src/Room.ts (1144, +70 since last review), ConnectionManager.ts, tickRecords.ts

Problem: Room grew — it now also owns the sims[] worldState feeds (ballRoster/crawlRoster emit sites) on top of wireIds, spectators, lastSentPositions, session tokens. The departPlayer funnel removed the correctness urgency, but Room is drifting toward being the place where everything meets.

Solution: RoomAudience (connections + spectators + wire-id lifecycle + last-sent + purge()), and consider hoisting the sims' worldState emit loop into a small RosterFeeds — it's a periodic-broadcast concern, not game semantics.

Benefits: delivery semantics in one place with a socket-level test surface; mostly hygiene now.

4 · Bot perception fork — senses are the remaining split

Files: shared/bot* (~5k LoC) · server_bun/src/serverSenses.ts (1015) vs client botSenses

Problem: brains are shared; eyes aren't. A sensing fix on one side silently diverges the other — and the user's live WIP is in shared/botBrain.ts, so this lane is hot right now.

Solution: hoist perception decisions into shared behind a narrow spatial-query interface; each side supplies its LOS/heightfield adapter. Then the twin-brain test covers senses too.

Benefits: one perception truth; offline/P2P bots stop being second-class. Caveat unchanged: raycast plumbing stays per-side.

5 · Declared-but-unused verbs + hitscan residue

Files: shared/worldModel.ts, server_bun/src/CombatHandler.ts

Problem: small but real drift risk in the new table: flagSpawn/flagGone/pickupKnock are declared with no emitter — dead declarations; and true-hitscan + client-triggered deployables (proxy/satchel) still ride the claim path the rest of combat deleted.

Solution: either emit the declared verbs or drop them (the conformance test should probably fail on declared-never-emitted verbs eventually); finish the claim-path cleanup so aoeShot/shot-era adjudication code retires when its last weapon leaves.

Benefits: keeps the table honest — a declaration that means nothing is worse than none.

Top recommendation: #1 — generated replicas finish C5

The wire half of C5 is done and pinned; the object half isn't. Extending the same declarations to replica construction is the continuation that turns "protocol can't drift" into "entity truth exists once". #2 is the proven bug-lane fix at lower risk. #5 is the cheapest honesty pass on the new table — one round, not a project.
