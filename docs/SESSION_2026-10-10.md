# KRIBES Session Notes — 2026-10-10

Reference log of the bizarre physics/netcode bugs chased down over two days
of live-play dumps. Format: symptom → root cause → fix (commit). Most were
found from `alt+Q` diag dumps, not reproduction — the dump canaries and
impulse logging added along the way are now permanent instrumentation.

## The "invisible shove" arc (local player displacement)

**Symptom**: "something keeps knocking me around invisibly" — periodic
yanks with no visible source.

- **Arena pull had zero feedback** — `RoomArena` out-of-bounds enforcement
  yanked players every 2s with no visual. The dome was `BackSide`-only, so
  from *outside* — exactly where a shoved player stands — it rendered
  literally nothing. → dome `DoubleSide` + 0.6s flash per pull + an amber
  `serverWarn` once per excursion (`62a711b3`, `47d6f71e`). Then JP called
  the mechanic stupid: **yank removed entirely** (`e26866f5`), banner kept.

- **Unstamped wire knockbacks were invisible** — server-authoritative
  impulses the client never predicted shoved with no blast painted.
  → both knockback and pull branches now paint the explosion at the wire
  position (`630e6cea`, `f1412992`).

- **Enemy shell direct-hits double-shoved** — `hurtLocal` paid a flat
  4-force knock AND the detonation's T1 blast shove paid its own, same
  origin same frame (the paired `X+3.3` in the impulse log). The server
  grants a direct-hit victim exactly ONE displacement
  (`combatBlast impulseOnly`). Offline rooms AND online bot fights were
  double-paying. → blastless hits keep the flat knock, blastful hits let
  the detonation pay (`785c0b9d`).

- **Stuck `jetPending` = "nuked into the sky"** — RMB jet flag sets on
  mousedown, clears on mouseup. A mouseup landing off-page (pointer-lock
  drop, alt-tab, OS dialog) leaves the flag held: full-tank burn straight
  up (~velY 21), recharge, relaunch, forever. → held input clears on
  pointer-lock loss + window blur (`627229fe`).

## The "ghost hits / drifting bots" arc (remote player truth)

**Symptom**: "I hit an enemy heavy 10 times with a bombard and he didn't
die" + bots rendered 53–166m from their wire positions.

- **Datagram-lane flap killed the whole session every ~2.3s** — the WT
  unreliable lane dying triggered a full reconnect; each reconnect froze
  remotes (dumps showed bots 50–160m off server truth) and orphaned
  predicted server-simmed shells → ghost hits. → lane death degrades to
  reliable-only (`d679f30c`).

- **Ghost-shell warn cried wolf** — fired on sub-RTT hits whose bind echo
  hadn't round-tripped yet. → 0.6s bind grace (`1d5d86fd`).

- **Predicted blasts stacked impulses into remote dead-reckoning** — every
  predicted blast re-seeded `simulatedVelocity` additively and re-armed
  the 0.6s prediction window. Under mortar spam (the fight cluster all 4
  drifting bots sat in), timer never expired and each blast stacked more
  velocity — remotes accelerated away from truth. → re-predict inside an
  active window is a no-op (`4c82bebd`, pinned by `9c72aa87`).

- **Dead-reckoning could drift without bound** — belt-and-suspenders cap:
  horizontal extrapolation freezes 40m from last wire truth (`8bd3e6f6`).

- **Zombie transport: dead socket, no re-dial** — `new WebSocket()` to an
  unreachable host parks in CONNECTING for the OS TCP timeout (~2min)
  firing zero events; the retry loop only re-arms on 'close'. Dump read:
  `connected:false`, `send dropped ×1600 "no live lane"` accumulating
  80s+, projectiles snapping 61–160m on stale records. → 10s handshake
  watchdog force-closes the socket so retries cycle (`213daa34`).

## Sim/test bugs

- **`hp=NaN`** — `mods.regenRamp` was read but never declared on
  `PerkMods` → `undefined * dt` under Regenerator. Declared + the
  regenerator ramp implemented (`630e6cea`, `9c19cc91`).

- **Ground-contact rewrite ate launches** — `c127e837` dropped the
  world-up launch gate: impulse bodies inside the snap band got
  re-grounded, eating knockback launches → correction spam. Restored
  `vel.y <= groundLaunchVel` in all three branches (`034e1b29`).

- **blastShove test pinned its victim *buried*** — the staged position was
  marginally under terrain; `unburyTick` re-seated the shadow every 0.5s
  and erased the shove mid-test. Repinned at real stand height
  (`39767aba`).

- **Net test bridges were less loss-tolerant than production** — they
  lacked `InputStream.prev` in-packet edge redundancy. Bridges now ride
  `prev` like production (`2ff5ecf7`).

## Bot cap-route arc (capRun)

The 775m katabatic flag run was a *stack* of independent bugs, each
exposed by fixing the one above it:

1. **Breach re-arm loop** — while a `breachGoal` owned the feet, orbit
   counters measured "not closing on goal" against the escape itself and
   armed the next breach for 25s, forever (`ed40722d`).
2. **Carrier beeline gap** — `flagGoal` hands `own.home` from <200m, but
   the steerer's committed beeline stopped at 60m; 60–160m out, slot
   repellers orbited the carrier ~80m from its own stand (`b51b7912`).
3. **Runner beeline gap** — same hole outbound: quiet-approach ring sits
   ~140m from the enemy stand, runner beelined only inside 60m → ~160s
   orbiting the approach. Runner now beelines 160m symmetric
   (`6862ece1`).
4. **Test pin clipped real caps** — the 320s budget cut a completed 347s
   cap by 8s. True orbits read `caps=0` at ANY budget, so the orbit
   detector needs no tight window → 480s (`6862ece1`).
