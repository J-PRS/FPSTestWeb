# VFX Overhaul — diagnosis + plan (2026-10-03)

JP: "completely redo and clean up the vfx system its a HUGE mess" — and the
symptom keeps recurring: streaks/smudges across the map survived THREE
separate fixes (updateVfx teleport-guard, rubberband emission suppression,
ribbon pool staleness). Each fix was correct; the class keeps finding new
doors. That's the architecture talking.

## What's actually wrong — one root class, many symptoms

**Emission-by-movement.** Both trail technologies deposit geometry along
the path the emitter traveled between frames:

- `QuarksTrail.emitSegment()` moves a quarks emitter to `host.pos`;
  `emissionOverDistance` deposits `dist * ppu` particles along the sweep.
- `RibbonTrail.push()` appends a sample; the strip spans last→new sample.

Any position discontinuity the runtime doesn't know about — teleport,
respawn, resync sweep (renderOffset decay), pool checkout landing at a
stale pos — deposits geometry across the gap. The defense is "every
caller remembers to teleport()/clear()/resync" — we already missed three
paths. There are ~8 emitter-moving call sites and every future one is a
fresh opportunity for a sky-streak.

**Manual ownership contract, enforced by detectors not structure.**
Ribbon/quarks handles follow stop()→update-until-done→dispose(). Nothing
enforces it; instead the system carries SIX violation detectors built up
over time: `nanPushes`, `zombiePushes`, `orphans()`, `reapedStale`,
`litAudit`/`sweepLit`/`reapedLit`, `teleportJumps`. A healthy system
doesn't need six leak alarms — it needs a model where the leak can't
compile. Every detector exists because a contract violation shipped.

**Duplicated infrastructure.**
- Two trail technologies side by side (hand-rolled RibbonTrail over
  TrailBatch; QuarksTrail over a quarks ParticleSystem pool) plus
  trailParticles.ts — three ways to leave a line behind something.
- ≥4 free-list implementations: RibbonTrail static pools ×2 (billboard
  split), vfxRuntime keyed pools, batchPool for TrailBatch, blast/puff
  emitter pools in vfx.ts.
- Diagnostics spread over trailDump, RibbonTrail.dump/identify/orphans,
  litAudit, batchStats, trailStats, poolDump — Alt+Q and visAudit have to
  know all of them.

**Double-ownership is structurally possible.** Pooled objects re-enter
the pool while still referenced (sweepStale disposed a live one once —
"first owner's stop() killed both trails"). Disposal is an object flag
(`inPool`), not an identity check — a stale reference can't be told
apart from a live one.

## Target architecture (researched patterns)

Representation-first / stable-slot pooling (three.js WebGPU skill, plume,
Alex Tardif's particle manager, the Enshrouded GPU-particle slides all
converge on the same shape):

1. **The runtime owns emitter motion.** Callers never move an emitter.
   Each frame, `updateVfx` reads the host's position (a getter, not a
   moved object), computes the delta once, and decides centrally:
   deposit (normal travel) vs resync (discontinuity). "Forgot to
   teleport" becomes impossible — there is no emitter to forget.

2. **Generational handles.** Slot = index + generation. acquire() bumps
   the generation; a stale handle dereferencing slot N hits gen mismatch
   and is refused. Double-ownership and use-after-pool die at compile-ish
   level instead of being reaped by sweeps.

3. **One lifecycle state machine per handle kind.** acquire → live →
   stopped → draining → released. Transitions only through runtime
   methods; `sweepStale`/`sweepLit` retire as detectors become redundant.

4. **One trail technology.** RibbonTrail (deterministic, one draw call
   via TrailBatch, already tagged/probed) is the survivor; QuarksTrail
   + trailParticles fold into it or get deleted. One way to leave a
   line = one place for the invariant.

5. **One pool + one diag surface.** `takeSystem` generalizes to all
   pooled visuals; Alt+Q/visAudit read a single census export.

## Phases

- **P0 — census + tests first.** Pin current pool/lifecycle semantics in
  vitest (acquire/release, stale-handle push, double-dispose, overflow
  batch), same lesson as the session suite: define "correct" while the
  old code still stands.
- **P1 — runtime-owned emitter motion.** `TrailHost { pos(): Vector3, vel(): Vector3 }`;
  updateVfx does the emit/don't-emit decision. Caller teleport()/clear()
  calls deleted — that's the streak class closed for good.
  **LANDED 2026-10-01:** `TrailDriver` in vfxRuntime.ts — a host registers
  `{pos, vel, emitting?()}` + its emitters + ribbons once; updateVfx ticks
  every driver each frame, runs the single jump detector (vel*dt*3 + 4),
  and cuts emitters+ribbons on a discontinuity. Projectile's emitTrails
  backstop and every caller-side teleport()/clear() deleted (advanceBy,
  rayBurst); deployRockets drives its ribbons through the same registry.
  Per-layer jump cuts stay as redundant tripwires.
- **P2 — generational slots.** TrailBatch slots gain a gen word; dead
  handles refuse pushes structurally. Retire zombiePushes/sweepLit as
  the paths that made them necessary are removed.
- **P3 — converge trail techs.** Port QuarksTrail hosts to RibbonTrail
  (or accept the quarks deposit only via the P1 runtime); delete the
  losing implementation + its pools.
- **P4 — unify pools + census.** One `takeSystem`-style pool for all
  visual handles; one `vfxCensus()` feeding Alt+Q and visAudit.
- **Exit:** a week of soak + Alt+Q with zero `teleportJumps`,
  `zombiePushes`, `reapedLit`, `unowned` — the counters stay as
  *tripwires*, not load-bearing fixes.

## Non-goals / parked

- GPU particles (TSL compute, dense-swap buffers): right end state, wrong
  now — WebGPU isn't our compat floor. CPU path stays, designed so a
  compute backend could replace the sim later.
- Blend/look pass (colors, sizes): only structural work here.
