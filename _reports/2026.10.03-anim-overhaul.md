# Animation/rig overhaul — diagnosis + plan (2026-10-03)

Symptoms JP hit: "medium model still tposing a lot", the `Animation not
found: Idle/Sitting` spam, per-class clip weirdness that keeps needing
one-off fixes. Same failure shape as netcode/VFX: the invariants live in
caller discipline and layered patches, not in the structure.

## What's actually wrong

**Clip resolution is a per-variant waterfall of code, not data.** State→clip
resolution for 9 states × 6 variants (robot, knight, mannequin,
scifisoldier, cybersoldier, vexa/polyart) is spread over ANIM_NAMES,
KNIGHT_ANIMS, CLASS_BODY_SPEC.anims, mannequinClip() overrides, the
directionalClip() KevDev path, and if-chains inside forceAnimationState.
A variant's coverage is unanswerable without reading all of them — which
is how cyber shipped zero native clips and every state silently resolved
to a missing fallback until the bake landed.

**Runtime retarget bake = a T-pose window by construction.** `bakeUALClips`
runs async after model load on the first live instance; zero-native-clip
variants hold bind pose for that whole window. The 'park on idle' fix
helps but doesn't close it — any state resolving to a still-missing clip
still returns early. The bake also costs CPU on the load path and its
correctness is hand-tuned per rig.

**Retarget correction is four layered patches.** rest-pose localOffsets
(torso-only, per-variant regex), fixHip (hip translation delta), unwindDirYaw
(directional clip yaw), alignHipYaw (outlier first-frame yaw measured at
runtime). Each fixes one rig quirk discovered the hard way; the next
foreign rig needs a fifth patch, and they're all runtime code mutating
baked clip data — invisible until rendered.

**Asset soup.** 10+ mannequin GLB variants + 4 source anim packs
(robot-anims, robot-anims2, kevdev, mannequin-as-source) + 7 bone maps.
Which pack feeds which variant lives in SPECS' `variants`/`mapByVariant`
filters — a second place a new rig can be miswired.

## Target architecture

Retargeting is **build-time data**, not runtime code — same lesson as
vmdump/genfield: bake offline in `_tools/`, ship the results, verify at
load. State→clip becomes **one declarative table** a coverage test can
enumerate; a missing entry is a load error, never a silent T-pose.

## Phases

- **P0 — coverage matrix test.** Enumerate variant × state → resolved
  clip name; pin the current waterfall's answers (including the known
  gaps) so restructuring can't silently change behavior. This alone
  documents every uncovered state.
- **P1 — offline bake.** Move bakeUALClips into `_tools/animbake`:
  produces per-variant clip packs (or merges into the class GLBs).
  Runtime loads clips, deletes the async bake path, T-pose window dies.
  The four correction passes move INTO the bake — runtime stops mutating
  clip data.
- **P2 — one ANIM_TABLE.** `ANIM_TABLE[variant][state] -> clipName` in
  playerClips.ts; forceAnimationState becomes a table lookup + play.
  Coverage checked at load (warn + idle hold if a bake is missing, but
  the matrix test keeps every shipping variant complete).
- **P3 — asset/manifest cleanup.** One RIG_MANIFEST (url, boneMap,
  sources, yaw/fit) per variant replacing SPECS + CLASS_BODY_SPEC +
  bone-map constants scattered across two files. Retire dead mannequin
  variants to .old.
- **Exit:** zero `Animation not found` in a 30s soak across all classes;
  adding a rig = one manifest entry + one bake run; coverage matrix
  stays green.

## Non-goals

- Blend-tree/state-machine replacement (UE-style locomotion blending) —
  state-pick + phase-carry already covers the feel; not the bug source.
- GPU skinning / instanced remotes — a render-perf topic, separate.
