# Weakest-Links Audit — 2026.10.01

Scope: client/src, server_bun/src, shared (~98.5k lines TS). Method:
marker scan, size scan, wire/alloc/type-safety scans, structural reads of the
largest modules. Both tsc clean; oxlint clean; 127 scenario + 43 client tests.

## Verdict first

The codebase's hard plumbing is in better shape than its creature/rig layer.
Netcode, sims, pooling, and tests have been through several overhaul rounds
and it shows — the weakest part is the **third-person body/weapon/anim
pipeline**, which has cost more iteration hours than anything else recently
and is still held together by three parallel mount paths and per-variant
hand-tuned numbers.

## Ranked findings

### 1. Third-person rig pipeline — the weakest part
- **Where**: `client/src/entities/PlayerModel.ts` (1315L) + hold/mount code
  spread across CyberSoldier/HeavyModel/rig manifests.
- **Evidence**: three coexisting weapon-mount paths (hand-bone child,
  model-root socket fallback, procedural hold bake). Per-variant solved
  mount quats hardcoded as raw quaternion components. Retargeted arm tracks
  from the mannequin bake land wrong on the cyber rig and had to be
  suppressed by posing the arm chain toward bind pose every frame.
- **Impact**: every class/weapon/pose combo is a fresh tuning exercise;
  bugs surfaced as "arm flailing" for multiple rounds. Highest
  cost-per-fix ratio in the project right now.
- **Fix**: one mount contract — a per-rig `gunMount` record
  (bone, local pos, solved quat, size) in the rig manifest, one code path
  that consumes it, delete the socket fallback and the procedural arm
  override in favor of a baked "hip-fire hold" clip variant per rig.
- **Effort**: Medium.

### 2. Combat resolution spread across ~8 server files
- **Where**: `CombatHandler.ts`, `ballCombat.ts`, `combatAoe.ts`,
  `combatBlast.ts`, `botBeam.ts`, `weaponStats.ts`, `botArsenal.ts`,
  `serverSenses.ts` (945L).
- **Evidence**: damage paths for bolts/balls/AOE/blasts/beams each have
  their own hit-resolve and friendly-fire rules; "who can damage whom"
  is not readable in one place.
- **Impact**: the selfK ~6-9% regression and grab-suicide bugs lived
  here — identical splash-vs-self rules are easy to get subtly different
  per path. Audit surface too wide for "server owns every outcome".
- **Fix**: funnel all damage through one `applyDamage(victim, amount,
  kind, attacker)` choke point that owns self-splash rules, kill-credit,
  and protection windows.
- **Effort**: Medium.

### 3. Bot senses: O(bots × players) per channel, no spatial index
- **Where**: `serverSenses.ts` — at least 5 separate
  `for (const q of players.getAllPlayers())` scans in one sense build
  (lines 181, 210, 223, 444, 762).
- **Evidence**: each channel (positions, pickups, shells, noises, foes)
  re-scans the full player map per bot think tick. Staggered think
  phases hide it at current scale.
- **Impact**: fine at ~20 bots × 8 players; quadratic at the 64-bot
  target. This is the known cost wall before big battles.
- **Fix**: build the "visible actors within R" candidate list once per
  sense tick (grid or single pass), feed all channels from it.
- **Effort**: Small-Medium.

### 4. gunlab.ts is a 1355-line dev-tool monolith
- **Where**: `client/src/gunlab.ts`.
- **Evidence**: archive picker, swarm preview, viewmodel lab, bake
  toggles, lighting rigs all in one file.
- **Impact**: it's the project's diagnostic workbench — where a feature
  is hard to inspect, bugs stay hidden (the turretter bake issue was
  only resolvable by building a separate replica page).
- **Fix**: split into `lab/` panels (archive, swarm, viewmodel); low
  urgency — dev-only.
- **Effort**: Small.

### 5. Asset weight: ~80MB in public/assets, 80MB dist
- **Where**: `client/public/assets` (models, heightmaps, skyboxes).
- **Evidence**: 149 bin/png payloads; GLBs and T2-derived textures are
  unoptimized originals.
- **Impact**: first-load cost fights "Krunker accessibility" — a cold
  tab on a slow pipe waits a long time.
- **Fix**: draco/meshopt-compress GLBs, KTX2 or downscaled textures,
  heightmaps already binary — biggest single UX win available without
  touching gameplay.
- **Effort**: Medium (pipeline work, low risk).

### 6. Two parallel bot stacks (confirmed duplication)
- **Where**: `client/src/game/bot*.ts` (~11 files: bots, botBrain-wrap,
  botSenses, botFire, botKill, botEnergy, botMatch, botRabbit, botCtf,
  botWatchdog, botSheep) vs `server_bun/src/bot*.ts` (ServerBots,
  serverSenses 945L, botDrive, botRoster, botSheep, botWatchdog,
  botArsenal, botCommand).
- **Evidence**: `botSheep.ts` exists on BOTH sides with different
  algorithms — client charges 0→100 on four channels, server drains
  100→0 on energy conversion. `botWatchdog.ts` same pattern (245 diff
  lines). Both sides wrap shared/botBrain but re-implement the entire
  sensorium + metering.
- **Impact**: every behavior fix must be written twice — or worse,
  written once and silently divergent (offline bots ≠ wire bots). This
  is the drift trap JP suspected.
- **Fix**: move senses/sheep/watchdog to shared/ behind a "body source"
  interface (offline GameBot vs wire player), so one implementation
  feeds both stacks.
- **Effort**: Large (but kills a whole bug class).

### 7. Dead duplicate files in src
- **Where**: `client/src/gunlab copy.ts` (34KB, unreferenced, still
  typechecked), `vertexAO copy.ts.old`, `vmBaked copy.ts.old`.
- **Fix**: `gunlab copy.ts` → `.old` per convention. Trivial.

## What's NOT weak (checked, healthy)

- Wire protocol: binary on hot paths, JSON only for rare events.
- Tests: 127 scenarios + 43 client, both tsc clean.
- TODO/FIXME/HACK count: zero. Empty catches: only fire-and-forget I/O.
- Per-frame allocs: hot loops use module-scope scratch temps.
- `.old` pile: 34 files — mostly stale assets, scheduled user cleanup.
