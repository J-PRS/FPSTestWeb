# Netcode & Session Architecture Overhaul

**Date:** 2026-10-03
**Status:** Proposal — validated against published netcode literature
**Scope:** server_bun session/transport/ingress layers, client reconnect policy, shared/ purity

---

## Executive Summary

The core architecture is **correct**: authoritative server, shared deterministic
sims, claim-based combat, edge-event streaming for creatures — this matches the
Quake/Source model and the Tribes ghost-event model it was inspired by.

The recurring production failures (anti-cheat kick loop, join-throttle lockout,
idle-reaper loop, reconnect storms) are **not** sim bugs. They are failures of the
**session/liveness layer**, which was never given the same rigor as the sims, and
of **transport tiering**, which introduced concurrency complexity that layer was
never designed to absorb.

Three killers in one session had one shape: *a timeout/verdict decided a live
player was dead, and there was no single place to check that decision.*

| Failure | Killer | Why it fired |
|---|---|---|
| Anti-cheat kick loop | `moveJudge` | Spawn teleports read as implausible; judge didn't know legitimate warps |
| Join-throttle lockout | `SessionManager` | Reconnect counted as a fresh join against a 30s window |
| Idle-reap loop | `tickRecords.reapIdle` | `lastSeen` stamped by only 2 of ~25 message types; `inputMove` didn't count |

## Root-Cause Audit

### 1. Session lifecycle is implicit — the primary defect

A player's identity is spread across **six independent stores**, none authoritative:

- `ws.data.playerId` — socket tag
- `room.disconnected` — grace map + timers
- `specRooms` — spectator index
- `playerRoom` — room index
- `SessionManager` — tokens + join-throttle map
- `PlayerManager.lastSeen` / `lastPosCheckTime`

Any system can write *some* of them; no system owns *all* of them. Close/kick
paths are likewise scattered: `SessionManager` has ~10 `ws.close()` sites,
`tickRecords` removes via `onRemove` callback, `moveJudge` kicks, `GameServer`
runs a 15s join-timeout, `RtcServer`/`WtServer`/`RtcRelay` close their own
sockets. The stale-socket guard in `GameServer.onClose` (`getConnection !== ws`)
was bolted on *after* it bit us — a symptom of lifecycle being emergent rather
than modeled.

### 2. Transport tiering manufactures the races grace must absorb

Client `TieredTransport` (~380 lines) probes RTC → WT → WS with miss-caching,
flap detection, generation epochs, and orphan teardown. Server-side, `RtcServer`
and `WtServer` wrap channels in fake `ServerWebSocket`s, so one logical player
appears as several sequential/overlapping socket objects. The reconnect-storm
`gen` epoch and flap breaker exist *purely to defend against complexity the tier
layer introduced*. Meanwhile the measured WT datagram loss was ~47% on loopback —
the unreliable lanes aren't paying rent.

### 3. `RoomInfo` is a ~35-slot callback grab-bag

Adding flag-knockback required `flagsKnock` next to `pickupsKnock`,
`deployBlast`, `preySplash` — four parallel fields for one concept (AOE impulse).
Every cross-domain feature costs: protocol type + validation + handler case +
RoomInfo field + Room wiring + sim method + test. Heal Grenade shipped for bots
but not humans because the feature matrix lives in *wiring*, not data.

### 4. No command queue — messages mutate mid-tick

`handleMessage` mutates authoritative state at packet-arrival time, interleaved
arbitrarily with `TickLoop` phases (sims → authority writeback → records →
fanout). Ordering is real-time, not sequenced — a direct contributor to the
flaky `netbot` jitter test.

### 5. Two clocks, zero enforcement

`simNow()` vs `Date.now()` is documented in `simClock.ts` but `Date.now()`
appears in ~40 server files. Sims, claims, judges, and session code mix clocks
on the honor system.

### 6. `shared/` isn't platform-pure

Unguarded `process.env` in `botHunt`/`botBrain` crashed the browser loop
(fixed). The pattern is unenforced — next unseeded `Math.random()` or Node
global lands the same way.

### 7. Claims have no uniform acknowledgement

`shot` has `shotId` binding + `shotRejected` — the good pattern. `creatureHit`,
`deploy`, `heal`, `repair`, `environmentDamage` are fire-and-forget;
`pendingHits.clear()` on reconnect silently drops them ("predicted hit never
confirmed"). The client can't distinguish *rejected* / *transport-lost* /
*expired*.

### What's fine — keep

- Authoritative model and claim validators (`claimLedger`, `CombatHandler`)
- Shared deterministic sims + edge-event streaming (`ballSegment`, `crawlEvt`)
- `protocol.ts` — single definition site, `PROTOCOL_VERSION`, `stateHash`,
  `correction`, `ackSeq` machinery
- `tickRecords` interest tiers + suppression — proven, measurable
- `harness.ts` scenario-test pattern — gaps are coverage, not approach

## Research Validation

### Tribes engine networking model (Frohnmayer/Gift)

One dumb connection layer reporting packet delivery status; **five stream
managers on a single socket** — events, ghosts, input moves, static datablocks,
strings — each with its own delivery guarantee. Transmission records give every
packet a delivery notification back to its stream manager.

- *Confirms:* one transport, many stream guarantees — not three parallel
  socket transports. WS-first is *more* faithful to the Tribes model.
- *Confirms:* generalize `ackSeq` into a delivery-notification layer for all
  reliable traffic (Phase 5).

### Quake 3 / Valve Source

Client sends one `usercmd` per frame; server **queues and drains commands at a
defined point** — "the only time players are ever updated." Source stamps
commands with `tick_count` and clamps lag compensation (`sv_maxunlag`).

- *Confirms:* Phase 3 command queue.
- *New enhancement:* **command-clock feedback**. When input arrives targeted at
  an executed tick, the server tells the client it's behind — don't silently
  drop/reuse. Our `inputMove` has `seq` but no skew-correction path; a drifting
  client gets commands dropped forever.

### Colyseus (production WebSocket game framework)

`allowReconnection`, `_reservedSeats`, `reconnectionToken` as bearer capability
— our proposed `SessionRegistry` maps 1:1. Three details to steal:

- **`minUptime` (~5s):** no auto-reconnect unless the session lived ≥5s. This is
  *the* guard against reconnect-flap loops — a session that never stabilized
  doesn't get retried.
- **`maxEnqueuedMessages` (~10–16):** during disconnect, client queues outbound
  messages with a bound and flushes on reclaim — `deploy`/`chat`/`classUpdate`
  survive a blip instead of being cleared.
- **Token rotation:** reconnect token rotates on each successful reclaim —
  kills stale-token replay.

### NSDI 2025 — browser networking evaluation

Academic measurement of WS / RTC DataChannel / WebTransport under game
workloads: WS is simple reliable+ordered (HOL blocking under loss); RTC DC is
UDP-like but heavy multi-layer overhead; WT is theoretically best but
narrow/immature. For a correctness pass at small player counts, **WS-only is the
defensible baseline**; unreliable lanes matter only when HOL blocking is
measurably hurting.

### Gaffer on Games

Deterministic lockstep is recommended ≤4 players — our shared sims are
*server-authoritative replays* (correct side of the line). `stateHash`
mismatches are predicted "approximately-same" prediction divergence; recorded-
command replay (Phase 3) is the standard tool for separating divergence from
true nondeterminism.

## The Plan

Each phase leaves the game playable and testable. Phases 1+3 are one milestone
— they share the "who is this player and when does a packet take effect"
boundary and together fix the entire recurring bug class.

### Phase 0 — Guardrails ✅ (this session)

- `lastSeen` stamped on any valid message; reclaim stamps it.
- **Exit:** real 90s+ tunnel session survives; no `idle` closes in logs.

### Phase 1 — Session state machine + reconnect policy

- `Session` per playerId: `{ state, generation, socket, roomId, token,
  wallClockLastSeen }`. One `SessionRegistry` owns all transitions;
  `room.disconnected`, `playerRoom`, `specRooms`, socket tags become views.
- States: `connecting → joined → active → grace → reaped` (plus `spectating`).
- `sessions.terminate(id, reason)` is the **only** place a socket closes for
  lifecycle reasons — idle reap, kick, grace expiry, join timeout, replaced.
- Every socket callback carries `generation`; stale-generation callbacks are
  no-ops by construction — the ad-hoc `!== ws` guard is deleted.
- Reconnect token **rotated per reclaim**; reservation is single-use.
- Client: **`minUptime` gate** (no auto-reconnect under 5s lived), **bounded
  outbound queue** (~16 commands) flushed on reclaim.
- **Tests:** reconnect in grace; reconnect after grace (fresh join); duplicate
  join while active; stale onClose after reclaim; idle reap under `inputMove`
  stream; idle reap under `ping`-only; RTC-adapter double-close; Colyseus-style
  page-reload manual-token path.
- **Exit:** `netbot` jitter test deterministic-green; `ws.close` calls exist
  only inside the session layer.

### Phase 2 — WS-only production baseline

- `FPS_TRANSPORT=ws` prod default; probe path kept behind dev flag.
- All three listeners stay; metrics tag the negotiated tier.
- **Exit:** 30-min soak over the tunnel, zero reconnect loops.

### Phase 3 — Command queue + injected clocks

- `handleMessage` → validate → `room.commands.push(msg)`. Tick drains the queue
  as phase 0, then sims, then fanout. Late commands defer one tick — defined,
  not racy.
- **Command-clock feedback:** server reports client's queue depth / ahead-
  behind status (new field on `tickUpdate` or a `clockHint` message); client
  nudges its send clock — the Quake/Source pattern, prevents silent drift.
- `WallClock`/`SimClock` interfaces injected into `MessageHandler`,
  `SessionRegistry`, `moveJudge`, `claimLedger`, `respawn`, `PlayerManager`.
  Rule: `Date.now()`/`simNow()` only inside the two impls.
- **Bonus:** recorded command streams = replay files → Phase 7 determinism
  tests for free.
- **Tests:** command ordering in-tick; replayed commands → identical
  `stateHash`; sim-warp vs wall-clock isolation.
- **Exit:** replay determinism green; `Date.now()` in server src = 2 files.

### Phase 4 — `RoomInfo` → domain events

- `RoomEvent` union (`BlastResolved`, `PlayerDied`, `FlagDropped`,
  `DamageDealt`…); sims emit, consumers subscribe. The four AOE-knockback
  fields + `onKill`/`onHit` collapse into subscription wiring.
- `Room.ts` stops being the wiring hub; domain services get a narrow
  `RoomContext`.
- **Exit:** "AOE knocks X" = one subscriber file. Flag-knockback is the
  reference port.

### Phase 5 — Transmission-record layer + claim acks

- Message **classes carry their delivery guarantee** (correction to my earlier
  draft: Tribes is right — guarantees are a first-class protocol concern, not
  hidden transport detail): reliable-ordered (events, claims, rosters) vs
  unreliable-unordered (moves, input). On WS the unreliable class degrades to
  "drop stale seq server-side" — same code, no HOL cost.
- `claimSeq` on every claim type; `claimAck{seq, ok, reason?}` per claim.
  `pendingHits` becomes a real pending-claim ledger with classified outcomes:
  accepted / rejected(reason) / superseded / transport-lost.
- Protocol bump → v12.
- **Exit:** zero silent claim drops; HUD surfaces rejection reasons.

### Phase 6 — Shared purity + feature registry

- `SharedEnv` injected (rng, trace flags); lint ban on `process|Bun|fs|
  Date\.now` in `shared/`.
- Weapon/belt registry: one entry = stats + cost + slot + validator + client
  config. New belt item = 1 file, not 6.
- **Exit:** client bundle has zero `process` references.

### Phase 7 — Observability + test hardening + deploy

- Structured session-transition log (`sessionId, old→new, reason, wallAge,
  simTick`) — one greppable line per transition.
- `/metrics`: session-state histogram, reap decisions with `lastSeen` age,
  claim-reject reasons.
- Fix `netbot` flakiness properly (phases 1+3 likely fix the root cause).
- Asset-manifest check in the deploy path — missing GLBs fail the deploy, not
  the browser console.
- **Exit:** new `session-lifecycle` scenario suite green; 30-min soak with zero
  unexpected transitions.

### Phase 8 — Reintroduce transports (optional)

- RTC/WT return as **lane swaps on the same `sessionId`** — the game sees a
  transport migration, not a new connection. Hand-off drains in-flight commands
  before activation.
- Pursue only if WS shows measurable pain at target player counts.

## Sequencing Rationale

Phases 1+3 are ~70% of the fix — they convert "who is this player / when does a
packet take effect" from distributed side effects into explicit structure.
Phases 4–5 buy feature velocity; 6–7 are hygiene; 8 may never be needed.

Trade-off: 1+3 are a few days of careful work with feature work paused, vs.
recurring surprise-kicks every couple of weeks — and the deploy-and-play-with-
friends goal is blocked *by exactly these bugs*.
